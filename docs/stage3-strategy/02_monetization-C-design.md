## 0. ひとことで言うと
- **アプリの中で物を売らない。**「ギフト共有ページ（公開のほしいものリスト）」を**Web側**に作り、

## 1. なぜ「アプリ内アフィリ」ではダメか（最重要）
- **Apple ガイドライン 3.2.2**：アフィリエイトリンクが**アプリの主目的**になっていると**リジェクト（公開拒否）**される。
- **Amazonアソシエイト規約**：原則、**アプリ内**でのアフィリリンク利用は許可制／多くが規約違反になりやすい。
- → だから「アプリの中の楽天/Amazonボタン」に自分のアフィリIDを付けるのは**やらない**（今の `links.js` は“ただの検索リンク”のまま据え置き＝安全）。
- **回避策＝収益はぜんぶ「外部Webページ」に置く**：
  - ユーザーが「ほしいもの」を**公開リスト（Webページ）**にする。
  - その**ページを見た第三者（友だち）が買う**＝「自己購入」でもなく「アプリ内導線」でもない。
  - Apple は“外部サイトでの第三者購入”には課金しない／3.2.2にも当たらない。

## 2. 全体の導線（ユーザー目線）
```
[アプリ] ほしいものを保存（既存）
   │  ＋「ギフトに公開」をオン
   ▼
[Web] あなたのギフトページ  wannalog.app/g/あなたのID
   │   ・ほしいものが並ぶ（写真・タイトル・ひとこと）
   │   ・各アイテムに「これを贈る／見る」ボタン（＝アフィリリンク）
   ▼
[第三者] 友だちがページを見て、欲しがってたものを購入
   ▼
[収益] アフィリエイト報酬が発生（Web側で完結）
   ＋ 友だちがページを気に入る → アプリを知る（口コミ拡散）
```
- ポイント：**「誕生日・記念日に、欲しいものリストを送る」**という自然な動機に乗せる。
- アプリ側のボタンは「ギフトページを共有する（LINE/Xでシェア）」だけ。**売らない**。

## 3. アフィリエイトの仕組み（どこと組むか）
- **ASP＝アフィリの仲介会社**。国内は「**もしもアフィリエイト**」で**まとめ取り**が王道。
  - 1つ登録すれば Amazon・楽天・Yahoo!ショッピング 等をまとめて扱える。**登録は無料**。
  - **LinkSwitch**：Web上の普通の商品リンクを**自動でアフィリリンクに変換**してくれる仕組み（Web側だけで収益が完結＝アプリは無関係でいられる）。
- **表示義務（必須）**：2023年からの**ステマ規制**で、ページに「**広告／アフィリエイトを含みます**」の明記が必要。デザインに最初から組み込む。
- 大手の主な報酬率（目安・変動する）：Amazon 数%／楽天 1%前後／物販は薄利。**「数で回す」前提**。

> オーナーの作業（無料・任意・あとででOK）：もしもアフィリエイトの会員登録（メール＋サイトURL登録）。
> ※サイトURLは、後述の「ギフトページ」が立ち上がってからで良い。今は登録だけ先にしておくと早い。

## 4. 技術アーキテクチャ（卒業B＝サーバーが要る）
公開Webページを出すには、**ローカル保存だけでは無理**でサーバー（BaaS）が必要＝**卒業B**。
- **採用候補：Supabase**（無料枠あり・集計に強い・初心者向けドキュメント豊富）。
- 構成（シンプル版）：
  ```
  アプリ(Expo) ──公開ON──> Supabase(DB)：公開アイテムを保存
                                   │
  友だちのブラウザ <── 静的Webページ(Next.js/Vercel) <── Supabaseから読み取り
                                   │
                            アフィリリンク（もしも/LinkSwitch）
  ```
- **Webページの置き場所**：Vercel / Cloudflare Pages / Netlify（いずれも**無料枠**で個人規模なら足りる）。
- **ドメイン**：最初は無料サブドメイン（例：`wannalog.vercel.app`）でOK。独自ドメインは後で（年1,500円程度・任意）。

- **C1（無料・アプリ内の下ごしらえ）**：

  - 「贈ってほしい度／価格メモ」など軽いフィールド（任意）。
  - **アフィリリンク生成の純粋関数**を Web 用に用意（`buildAffiliateUrl(item, ids)`）。テスト付き。※**アプリ内では使わない**（Web側専用）。
- **C2（無料・Webモック）**：ギフトページの**見た目だけ**を静的HTMLで作る（`mockups/gift-page.html`）。データはダミー。

- **C3（ここで初めて要判断）バックエンド接続**：

## 7. リスクと対策
- **Apple 3.2.2 リジェクト** → 収益はWeb側のみ・アプリは「共有」だけ。アプリ内に楽天/Amazonアフィリを置かない。
- **Amazonアソシエイト審査（180日以内に3件成約しないと失効）** → もしも経由＋友だちへの共有で初動の成約を作る設計。
- **ステマ規制** → ギフトページに「広告を含む」明記を**デフォルトで**入れる。
- **個人情報／公開範囲** → 公開は「合言葉付きURL（推測されにくいID）」。本名・位置情報（撮影GPS）は**公開ページに出さない**設計を明文化。
- **初心者の運用負荷** → C3は「Supabase立ち上げ手順」を `app/README.md` に画像手順で残す。
