# マネタイズの算定と道のり（WannaLog）

> 2026-06 時点のまとめ。オーナー向けに、専門用語を避けてやさしく書く。
> 数字は「一般的な目安」であり保証ではない（料率・成約率は時期やジャンルで変動）。

## 0. いまの状態（正直に）

- **アフィリエイトはまだ1円も発生しません。**
  - アプリの購入リンクは Amazon・楽天・Google の**検索ページに飛ぶだけ**（商品個別ページですらない）。
  - **アフィリのタグ（紹介ID）が付いていない**ので、買われても報酬ゼロ。
  - コード上に土台（`app/affiliate.js`）はあるが、**どこからも使われていない**（あえてアプリ内では使わない設計＝Apple規約対策）。
  - **アフィリ提携（もしも・楽天・Amazon）も未登録**。
  - **Web共有ページ（本当の収益の場）が未実装**（共有はテキストのみ）。
- まとめ：**下準備は「コードの骨組みだけ」。実際に稼ぐには後述の Step1〜2 が必須。**

## 1. アフィリの収益“ざっくり算定”

### 計算の前提（目安）
- 平均料率：**約3%**（Amazon/楽天/もしも、ジャンルで2〜4%）
- 平均購入額(AOV)：**¥4,000**（ギフト用途ならもう少し高いことも）
- 1成約あたり報酬 ＝ 4,000 × 3% ＝ **約¥120**
- ファネル：アクティブ利用者のうち **購入リンクを押す ≈ 30%** → そのうち **買う ≈ 2%**

### 月あたりの売上目安（アフィリ単独）

| 月のアクティブ利用者(MAU) | 想定の月間アフィリ報酬 |
|---|---|
| 100人 | **¥70〜150**（ほぼゼロ） |
| 1,000人 | **¥700〜1,500** |
| 10,000人 | **¥7,000〜15,000** |
| 100,000人 | **¥70,000〜150,000** |

> ギフト用途は購入額・成約率が高めに出ることがあり、うまくいけば上の **約2倍**も。
> それでも結論は同じ：**アフィリは「規模(=人数)が出てからのボーナス」**。1万人を超えて初めて意味が出る。

## 2. サブスク/買い切りとの比較（こちらが本命になりやすい）

- 例：プレミアム **月額¥400**、無料→有料の転換率 **3%**、Appleの手数料 15%（小規模事業者プログラム）
- 同じ規模での比較：

| MAU | アフィリ(月) | サブスク(月・手数料引き後) |
|---|---|---|
| 1,000人 | ¥700〜1,500 | **約¥10,200**（30人×¥400×0.85） |
| 10,000人 | ¥7,000〜15,000 | **約¥102,000** |

→ **同じ人数なら、サブスクはアフィリの約8〜15倍**。しかも毎月読める（予測しやすい）。
→ 方針：**収益の本命は「サブスク/買い切り」、アフィリは“おまけ”**。

### サブスクにできる価値の例（将来）
テーマ追加 / ビジョンボードの枠無制限 / 通知の強化 / ウィジェット / バックアップ・同期 など。

## 3. アフィリを“実際に動かす”までの道のり

> アプリ内はアフィリを踏ませない（Apple規約）。**収益はWeb側だけ**で作る。

1. **Step1：媒体を用意して提携審査を通す**
   - もしもアフィリエイト（LinkSwitchで自動アフィリ化が楽）／楽天アフィリ（すぐ）／Amazonアソシエイト（審査あり・登録後180日で3件売上が必要）。
   - ⚠️ 審査には**公開されたSNSかWebサイト**が要る（アプリだけだと通りにくい）。＝先に発信媒体。
2. **Step2：収益の“場”を作る（ここが本丸）**
   - 「ほしいものリスト」を**URLで共有できるWebページ**を作る（無料：Vercel等）。
   - そのページの商品リンクを**もしもLinkSwitch**やタグ付与で**アフィリ化**（`affiliate.js`の`buildAffiliateUrl`が活きる）。
3. **Step3：集客**
   - SNS発信＋「誕生日・記念日にギフトページを共有」する導線。
4. **Step4：計測して改善**
   - クリック数・成約・**EPC（1クリックあたり収益）**を見て、文言や商品の出し方を改善。

## 4. 時系列の提案

- **7月**：$99払って**ネイティブ化（EAS Build → TestFlight）**＋**自分で毎日使い込む**（使用感・不満をメモ）。
- **8〜9月**：広げたい意思が固まったら、**媒体登録＋Web共有ページ**着手（実装は秘書が担当）。
- **それ以降**：人が集まればアフィリは自然発生。**規模が出たらサブスク導入**を検討（収益の柱）。

## 5. 結論（ひとことで）

- 今やるべきは**アフィリ準備ではなく「自分で使い込んで磨く」**こと。
- 収益化の順番：**良いアプリ → 利用者 →（広めるなら）SNS → Web共有ページ → アフィリ／その先にサブスク**。
- アフィリは“規模ゲーム”。**本命はサブスク**と理解しておくと判断を誤らない。
