# WannaLog MVP仕様書 v1.0

作成日：2026-06-19 / 担当：秘書（デザイン・批判家・市場調査の議論を統合）
前提：React Native (Expo)／テーマ Warm Cream／ホームは均一2列グリッド／達成はコレクションに飾る。
参考：オーナー提供のAI生成モック（5画面：ホーム／保存／マイリスト／詳細／マイページ）。

---

## 0. 設計の核（再掲）
- North Star：**「忘却を倒し、わくわくを灯す」**。整理ツールでなく「眺めるだけで叶いそうになる夢の地図」。
- 敵は「忘却」（オーナー実データ：行動できなかった理由はほぼ“忘れていた”、行動率30%）。
- 勝ち筋：**想起のタイミング精度（通知の質）**＋**眺めて楽しいビジュアルボード**。

## 1. MVPスコープ方針（“絞る”の正しい意味）
- **見て心が動く体験（横断ボード／ビジョンマップ／わくわくUI）は最初から作る**。
- **重い裏側（行動導線・API連携）は「食べたい」を軸に磨き**、他カテゴリは検索リンク等の簡易版で先行。
- **共有シート・ウィジェットはMVP対象外**（Expoで最難関）。アプリを開いて保存。
- **収益はMVPゼロ**。アフィリは詳細画面の「アクション」の一つとして自然に置く（Apple審査3.2.2対策＝主目的にしない）。

### MVPに入れる / 後回し
| 機能 | MVP | 後回し |
|---|---|---|
| ホーム（横断ボード・カテゴリフィルタ・検索） | ✅ | マソンリー化 |
| 保存（テキスト／URL〔OGP取得〕／写真添付） | ✅ | 共有シート、スクショOCR自動取込 |
| AI自動まとめ（タイトル・要約・カテゴリ・タグ提案） | ✅ | 精度向上・学習 |
| アイテム詳細＋アクション（食べログ/地図等） | ✅（食べたい軸を作り込み） | 予約API連携・価格追跡 |
| 達成チェック＋叶えたコレクション | ✅ | バッジ・月次Wrapped |
| リマインド（ローカル通知・時間ベース） | ✅（テキスト＋絵文字） | 写真付き通知、場所/習慣ベース |
| ビジョンマップ（写真グリッド表示） | ✅（簡易：コレクション/ボード表示） | マンダラート式の自由配置編集 |
| アカウント・クラウド同期 | ❌（端末内保存で開始） | ログイン・同期・公開リスト共有 |

## 2. 画面一覧（5画面＋通知）

下タブ：**🏠ホーム ／ 🔍検索 ／ ＋保存 ／ 🔔リマインド ／ 👤マイページ**

### 2-1. ホーム（ビジョンボード）
- 上部：ロゴ「WannaLog」＋🔔通知ベル（未読ドット）。検索バー「キーワードで検索」。
- カテゴリチップ（横スクロール）：すべて／🍽️食べたい／📍行きたい／🎬見たい／🛍️欲しい／💪やりたい／📖知りたい／✨その他。「すべて」初期選択。
- 「最近追加したもの」見出し → 2列グリッドの写真カード。
- カード：写真（左上に**カテゴリ色タグ**）／タイトル／日付 or 期限（近いものはコーラルで「あと3日」）／達成済みは金チェック。
- 右下：コーラルの＋FAB（または下タブの＋）。

### 2-2. 保存フロー
- 入力タブ：**［スクショ/写真］［URLを保存］［テキスト］**。
- 取り込み後「✨AIが内容をまとめました」→ タイトル・カテゴリ・要約・タグ・「いつまでに」を提案表示。
- ユーザーは確認・微修正のみ。コーラル「保存する」。
- 「いつまでに」は選択式（なし／今週／今月／日付）。タグはAI提案＋追加可。

### 2-3. アイテム詳細
- 大きな写真／タイトル／カテゴリ／タグ／期限。
- **アクション**（カテゴリで自動切替）：
  - 食べたい：食べログで探す／ホットペッパーで予約／Googleマップで見る／友達にシェア
  - 行きたい：Googleマップ／じゃらん・楽天トラベルで探す／シェア
  - 欲しい：楽天で探す／Amazonで探す（※アフィリは副次）／シェア
  - 見たい：U-NEXT/Netflix/Prime/映画.comで探す／シェア
  - やりたい/知りたい/読みたい：検索／リマインド設定／シェア
- 下部：チェックボックス「達成した！」、ブックマーク（保存先/コレクション）。

### 2-4. リマインド（通知）
- 一覧：これから思い出させる予定／期限が近いもの。
- 通知ポリシー：責めない・写真リッチ（将来）・週1〜2回・絶妙な1通。
- タイミング（MVP）：保存3日後／期限「今週」は金曜夕方／食べたいは昼前・夕方。
- 通知タップ→該当アイテム詳細へ直行（思い出す→即行動を最短に）。

### 2-5. マイページ
- 達成カウント（例 48/120）＋週次グラフ。
- 「最近達成したこと」チェックリスト。
- **ビジョンマップ**：叶えたい/叶えた写真のグリッド（＋追加）。MVPは閲覧中心、編集は簡易。
- 設定（テーマ、通知、データ）。

## 3. データモデル（端末内・MVP）

```
Item {
  id: string
  title: string            // AI提案 or 手入力
  summary: string          // AI要約（任意）
  category: enum            // 食べたい/行きたい/見たい/欲しい/やりたい/知りたい/読みたい/着たい/その他
  imageUri?: string         // 写真 or OGP画像 or なし(→カテゴリ色グラデ+絵文字)
  sourceUrl?: string        // URL保存時
  tags: string[]            // AI提案+追加
  dueTag?: 'none'|'thisWeek'|'thisMonth'|date
  reminderAt?: datetime     // ローカル通知予約時刻
  createdAt: datetime
  doneAt?: datetime|null    // 達成時刻（叶えたコレクション判定）
}
```
保存：MVPは端末内（AsyncStorage/SQLite等）。クラウド同期は後回し。

## 4. AI（自動まとめ）設計
- 入力：貼り付けテキスト／URLのOGP（タイトル・説明・画像）／（将来）スクショOCRテキスト。
- 処理：LLMに渡し、**タイトル・要約・カテゴリ・タグ・期限候補**をJSONで受け取る。
- 推奨バックエンド：**Claude API**。短文分類はコスト効率重視で **claude-haiku-4-5**（安価・高速）。要約品質を上げたい箇所だけ上位モデル。
- コスト注意：無料アプリなので、1保存あたりのトークンを小さく（短いプロンプト＋短い出力）。API鍵はアプリに直書きせず、軽量プロキシ（サーバーレス関数）経由が安全（後で設計）。
- OCR：MVPはテキスト/URL先行。スクショOCRは Phase 1.5（オンデバイスOCRが権利・コスト面で安全）。

## 5. アクションリンク仕様（MVPは食べたい軸を作り込み）
- 食べログ検索：`https://www.tabelog.com/rstLst/?sw=<キーワード>`（要確認）
- Googleマップ：`https://www.google.com/maps/search/?api=1&query=<キーワード>`
- 楽天/Amazon：検索URL（アフィリIDは将来付与、MVPは素のリンクでも可）
- 実装：`Linking.openURL`。MVPは「検索リンク」で十分。予約API等は後回し。
> 重要：アフィリは“主目的”にしない。アプリの主目的＝保存・想起・可視化。リンクは詳細画面の「アクション」の一つ。

## 6. 実装順（挫折しない順）
1. デザイントークン（Warm Cream配色・余白・角丸）を1ファイルに。
2. ホーム（均一2列グリッド＋ダミーデータ）で「眺めて楽しい」を先に体感。
3. 保存（テキスト手入力）→端末内保存→ホーム反映。
4. アイテム詳細＋アクションリンク（食べたい）。
5. AI自動まとめを保存フローに接続（Claude API）。
6. ローカル通知（テキスト）。
7. 達成チェック＋紙吹雪＋叶えたコレクション。
8. URL保存（OGP）→ 余裕が出たらマソンリー／写真付き通知／ビジョンマップ編集／OCR。
