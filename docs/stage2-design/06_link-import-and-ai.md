# リンク読み込み（OGP）と AI の要否・時期

> 2026-07。リンクから画像・タイトルを自動取得する仕組み（OGP）を Expo Go 上で実装した。
> どのサービスが効いて、どれが効かないか、そして AI（OCR）や共有シートの時期をまとめる。

## いま実装したこと（ネイティブ化不要・今すぐ使える）
- 保存画面でURLを貼ると **「リンクから画像・タイトルを読み込む」** ボタンが出る。
- リンク先の **OGP（og:image / og:title）** を取得して、空欄なら画像とタイトルを自動で埋める。
- 端末から直接 `fetch` するので、ブラウザと違い **CORS制限が無い**（＝多くのサイトを取得できる）。

## ◎ よく効く（OGPがちゃんとあるサイト）
- **楽天市場**（商品ページ）
- **YouTube**（サムネ＋タイトル）
- **一般ブログ / ニュース / お店の公式サイト / 個人サイト**
- **クックパッド / 楽天レシピ / note / Pinterest**
- 食べログ・ぐるなび（ページによる）

## △ 効きにくい（Bot対策・ログイン必須・JS描画）
- **Amazon** … Bot対策が強く、ロボット確認ページが返って失敗しやすい。
- **Instagram** … ログイン必須でOGPが削られ、ほぼ取得不可。
- **X（旧Twitter）** … カード用スクレイパー限定で、直接取得は不安定。
- **TikTok / 一部フリマ（メルカリ等）/ Cloudflare保護サイト** … 失敗しやすい。
- 短縮URL（amzn.to 等）… リダイレクトは追えるが、最終ページがAmazon等なら同じく失敗。

## なぜ「ほしもん」等はAmazon/IG/Xも取れるのか
- 端末から直接ではなく **サーバー側で取得**（良いIP・ヘッダー・リトライ・ヘッドレスブラウザ）している。
- **公式API**を使う（AmazonアソシエイトのPA-API＝審査+売上要件、楽天API＝無料）。
- サービスごとの個別対応をしている。
- → 競合レベルにするには **小さなサーバー（無料枠のCloudflare Workers/Vercel等）＋各API** が要る。ネイティブ化とは別に作れるが、新しい部品が増える。

## AI（OCR）は必要？ → リンク中心なら「無くてもいける」
- **リンク保存**：OGPで画像＋タイトルが取れる → **AI不要**。オーナーの読み通り。
- **AI（OCR＝写真の文字読み取り）が活きるのは**：リンクが無い/取れない場合。
  - 例：メニューやチラシの写真、**OGPが取れないIG/Xはスクショ→OCR**が現実的な代替。
- 結論：**まずはリンク（OGP）で大半をカバー。AIは「取れない所」の“予備”**という位置づけでよい。

## 時期（今できる / ネイティブ化後）
| 機能 | いつ | 理由 |
|---|---|---|
| リンクからOGP読み込み | **今できる（実装済み）** | 端末の fetch だけで完結 |
| 取得成功率アップ（サーバー＋API） | 別途（ネイティブ化と無関係に可） | 小さなバックエンドが必要 |
| 共有シート（他アプリ→WannaLogに送る） | **ネイティブ化後** | Expo Go では共有拡張を追加できない |
| AI / OCR（写真の文字読み取り） | **ネイティブ化後** | 端末OCRはネイティブモジュール |
| Web共有ページ（アフィリ） | いつでも（別作業） | Web側の話 |

## メモ
- OGPで取れた画像は**リモートURL**なので、端末を変えても消えない（手動で選んだローカル写真より丈夫）。
- 並べ替えは、ドラッグが実機で安定しなかったため **▲▼ボタン方式** に変更（確実に動く）。ドラッグは実機で確認できるネイティブ化後に再挑戦候補。
