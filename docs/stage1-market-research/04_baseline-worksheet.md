# 最小検証ワークシート①：あなたの「保存→行動率」ベースライン

> 目的：WannaLogの核心仮説は「保存したものを実際に行動に移せる」こと。
> その“現状値”を知らないと、アプリが効いたかどうか判定できません。
> **コードを書く前の5〜10分**で、あなた自身の「保存しても結局やらない率」を測ります。

## やり方（どちらか／両方）

### A. スクショ編（おすすめ）
1. iPhoneの写真アプリ →「スクリーンショット」アルバムを開く。
2. **直近30枚**をざっと見る。
3. そのうち「何かを“したい/気になる”と思って撮ったもの（店・商品・行きたい場所・見たい作品など）」を数える＝ **保存数 N**。
4. そのNのうち「実際に行動した（食べた・行った・買った・見た）」ものを数える＝ **行動数 M**。

### B. ブックマーク/Pocket等編（使っていれば）
- 同様に直近の保存20〜30件で、実際に行動・消費したものを数える。

## 記入欄

| 項目 | 数 |
|---|---|
| 見返したスクショ/保存の総数 | （例：30） |
| うち「したい」で保存したもの N | |
| うち実際に行動したもの M | |
| **行動率 = M ÷ N** | （例：4 ÷ 20 = 20%） |

メモ（行動できなかった理由で思い当たるもの）：
- 例）忘れていた / どこに保存したか分からなくなった / 面倒だった / 気が変わった など

## この数字の使い道

- この **行動率がベースライン**になります。
- 後でMVP（食べたい＋通知）を作り、その「達成チェック率」がこのベースラインを**明確に上回れば**、WannaLogは価値がある証拠。
- 上回らなければ、機能を足す前にコンセプトを見直します。

👉 数えたら、秘書（このチャット）に「行動率は◯%だった」と一言教えてください。私が記録します。

---

## ✅ 測定結果（2026-06-19・オーナー本人）

| 項目 | 数 |
|---|---|
| 見返したスクショ総数 | 30 |
| うち「したい」（欲しい/食べたい/やりたい/もの）で保存 | 30（＝全部が欲求系） |
| うち実際に行動した M | 9 |
| **行動率（ベースライン）** | **9 ÷ 30 ＝ 30%** |

### 質的インサイト（最重要）
- 行動**できた**もの：**その場で即・買った/やった**もの（衝動・即実行）。記憶に頼っていない。
- 行動**できなかった**もの：**ほとんどが「忘れていた」**。

### 戦略的含意
- WannaLog が倒すべき敵は **「忘却」**。
- 勝ち筋は **「ちょうど良いタイミングで思い出させる（想起のタイミング精度）」**。批判家の指摘とオーナーの実データが一致。
- MVPの達成チェック率がこの **30%を明確に上回れば**、WannaLogは価値があると判定できる（撤退条件の基準値）。
- 注意：30%のうち多くは「その場実行」分。WannaLogが本当に取りに行くのは、現状“忘れて落ちている残り”の部分。
